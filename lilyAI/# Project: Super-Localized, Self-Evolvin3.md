# Project: Super-Localized, Self-Evolving Omnitide Nexus (SLOEN) - Phase 3: Lily Core: Self-Awareness & Agentic Orchestration Framework (LCSAF)

## Objective
Generate the core Lily Core: Self-Awareness & Agentic Orchestration Framework (LCSAF) as a secure FastAPI application. This framework will house Lily's advanced capabilities, manage memory, orchestrate tool use (including direct dev computer interaction via OREA), and critically, **refactor and secure the previously generated OCKIFT-P components.**

## Key Requirements for LCSAF FastAPI Application
1.  **Project Structure:** Create a Python project (`lc_saf_project.tar.gz`) with `main.py` (FastAPI app), `requirements.txt`, `agents/` directory, `tools/` directory, and `memory/` directory.
2.  **FastAPI Application (`main.py` for LCSAF):**
    * **Initialization:** Standard FastAPI app setup.
    * **Dynamic JWT Authentication:** Implement a robust JWT authentication system.
        * LCSAF acts as the **JWT Issuer** for authenticated requests from the Architect's mobile app.
        * LCSAF acts as the **JWT Validator** for all incoming API requests (including from the refactored OCKIFT-P if it were to call back, and from the mobile app).
        * Securely generate and manage JWT secret keys (e.g., using `secrets` module, stored in an environment variable or secure config).
        * Endpoints for token issuance (`/auth/token`).
    * **Core Conversational Endpoint (`/chat`):**
        * Accepts text input, uses the local Llama 3 instance (via `ollama` or `llama-cpp-python` interface) for reasoning.
        * Integrates with a multi-vector memory system (see `memory/` below).
        * Orchestrates tool use (see `tools/` below).
        * Manages conversational context.
    * **Self-Improvement & Auto-Correction Module Endpoint (`/self_improve`):**
        * An internal endpoint (triggered by an internal agent or API call from a monitoring system).
        * Analyzes Lily's previous interactions, identified weaknesses (e.g., hallucinations, incorrect tool use, reasoning errors).
        * **Automatically generates new fine-tuning examples (`JSONL`)** based on these identified weaknesses and desired ideal responses.
        * Pushes these new examples to the **refactored OCKIFT-P `/ingest` endpoint** for continuous learning.
        * Initiates a fine-tuning job on OCKIFT-P via its `/fine_tune` endpoint.
3.  **Agents Directory (`agents/`):**
    * **`ockift_refinement_agent.py`:**
        * **CRITICAL TASK:** This agent, operating through LCSAF's capabilities, must generate new Python code that **rewrites and enhances the `app/main.py` and `fine_tuning_scripts/train.py` from OCKIFT-P** based on the following specific instructions:
            * **OCKIFT-P `app/main.py` Refactoring:**
                * **Replace HTTP Basic Auth with JWT Validation:** Modify all endpoints to use JWT validation (issued by LCSAF).
                * **Secure Storage Path:** Change `UPLOAD_DIR` and `FINE_TUNE_DIR` to `/opt/omnitide_nexus/uploads` and `/opt/omnitide_nexus/finetuned_models` respectively. Create these directories if they don't exist, with proper permissions.
                * **Advanced Data Processing in `/ingest`:** Implement:
                    * Robust sanitization (e.g., `bleach` for HTML, `re` for control chars).
                    * Semantic chunking (e.g., using a simple text splitter, or integration with a dedicated `langchain` component if possible without adding too many dependencies).
                    * Basic hash-based de-duplication.
                    * **Cryptographic Signing:** Generate a simple HMAC-SHA256 signature for each ingested data chunk using a secret key (from env var). Store this signature alongside the data to ensure integrity.
                * **Fine-Tuning Orchestration Enhancements in `/fine_tune`:**
                    * After `subprocess.run` for `train.py` completes:
                        * **Trigger Quantization & Pruning:** Call an *additional script* (generated by Co-pilot within `fine_tuning_scripts/optimize_model.py`) to apply INT8/INT4 quantization and basic pruning to the newly fine-tuned model.
                        * **Model Versioning:** Implement a clear versioning scheme (e.g., `llama3_omnitide_vYYYYMMDD_HHMMSS.gguf`) and symbolic linking for the `latest` model.
                        * **Rollback Mechanism:** Implement a robust mechanism to revert to a previous model version if the new one fails health checks or performs poorly.
            * **OCKIFT-P `fine_tuning_scripts/train.py` Refactoring:**
                * Modify `get_dataset` to explicitly handle **JSONL format for instruction-tuning**, ensuring proper parsing of "instruction," "input," "output" fields.
                * Integrate placeholder logic for **adversarial training techniques** within the `TrainingArguments` or `Trainer` callbacks (e.g., injecting adversarial examples generated by a separate module, or using libraries that support it).
            * **Output:** The agent must output the *rewritten code* for `app/main.py`, `fine_tuning_scripts/train.py`, and the *new* `fine_tuning_scripts/optimize_model.py`.
    * **`ollama_interface_agent.py`:** Agent for securely interacting with the local `ollama` instance (loading models, performing inference).
4.  **Tools Directory (`tools/`):**
    * **`ssh_executor_tool.py`:** A secure Python tool using `paramiko` (or similar) to execute commands on the dev computer via SSH.
        * **Authentication:** Uses the `omnitide_orea` user's SSH key (generated in Pass 1).
        * **Sandboxing:** Commands are wrapped in `firejail` or `docker run --rm` commands for strict isolation.
        * **Command Whitelist:** Only allows execution of commands from a predefined whitelist.
        * **Logging:** Logs every executed command, its output, and success/failure status.
    * **`file_manager_tool.py`:** Secure tool for reading/writing files on the dev computer (via OREA SSH agent).
    * **`git_tool.py`:** Secure tool for Git operations (commit, push, pull) on dev computer (via OREA SSH agent).
5.  **Memory Directory (`memory/`):**
    * **`vector_store.py`:** Implements a local vector database (e.g., `ChromaDB` or `FAISS` with `hnswlib`) for semantic memory.
    * **`structured_knowledge.py`:** Implements a simple SQLite-based key-value store or a lightweight graph database for structured facts.
    * **`context_manager.py`:** Manages conversational context and short-term memory.
6.  **Requirements File:** A `requirements.txt` listing all Python dependencies for LCSAF.
7.  **Docker Integration:** Include a `Dockerfile` for the LCSAF application, ensuring it runs with least privilege in a container.

## Output Format
A `tar.gz` archive containing the complete Python project structure for LCSAF (`lcsaf_project.tar.gz`), PLUS the **rewritten `app/main.py` and `fine_tuning_scripts/train.py` from OCKIFT-P, and the new `fine_tuning_scripts/optimize_model.py`**. Ensure the rewritten files are clearly distinguishable (e.g., `ockiftp_main_refactored.py`).
